# MIRPG Remote — visual UI review

**Date:** October 12, 2026  
**Evidence:** User-supplied Android screenshots and current Flutter source (especially `target_dashboard_page.dart`, `emulator_page.dart`, `monitor_control_view.dart`, `codex_page.dart` and `mirpg_remote_theme.dart`).  
**Scope:** Review and editable proposals. No production application changes.

![Five editable OpenPencil proposals](../exports/all-screens.png)

## Top five issues, in implementation order

| Priority | Current screenshot / code observation | Proposed UI and acceptance condition |
| --- | --- | --- |
| **P0 — Preview reliability** | Jarvis reports **Direct · 2 ms** while both PC previews say **Connecting** with black video. A healthy network session is not proof of a live frame. In `target_dashboard_page.dart`, the desktop `live` value may be true whenever an image exists even if it is stale. | Show separate host and preview states, track last usable frame, and display **Live**, **Starting**, **Stalled**, **Retry** based on real stream freshness. Keep other targets accessible. |
| **P0 — Guest dead end** | BlueStacks App Player 3 shows **Guest session is closed**, with only **Return to desktop**. This blocks the main remote-control workflow. | Provide **Reconnect guest**, **Restart preview**, and **Switch view** in place. Keep Back/Home/Recents usable whenever the guest input session is genuinely live; otherwise explain why unavailable. |
| **P1 — Codex command overload** | A Codex chat is dominated by a long, wrapped PowerShell command; task state says **History** with a prominent **Resume** action. | Make conversation readable by default and group tools, commands and output into collapsed activity. Show **Live / Running / Finished / Disconnected** accurately. Source now contains collapsed `ExpansionTile` tool activity, so check installed APK/version and actual initial expansion before changing code. |
| **P1 — Tiny Windows desktop** | A 2K Windows screen in a phone viewport is unreadable at full fit, and remote controls compete with the content. | Put **Readable** zoom next to **Fit** as a first-class mode, default appropriately on phones, surface a minimap and visible **Mouse / Keyboard / Right click / Targets** controls. Existing `monitor_control_view.dart` implements much of this; validate behavior and placement first. |
| **P1 — Connection recovery** | A generic dialog exposes a repeated WebRTC/fallback error and only **OK**, while other views can remain available. | Show a plain-language contextual error with **Retry**, **Switch view**, and optional diagnostics. Distinguish *PC offline* from *PC online, stream failed*. Preserve navigation after failures. |

An earlier screenshot also showed a null-check exception and a severe layout overflow on the Computers page. **Reproduce this on the current APK** before prioritizing a separate fix; it was not reproduced during this review.

## Editable proposals

1. **Overview:** one-tap Windows and BlueStacks cards, actual live thumbnails when available, separate boot and streaming states. Illustrative content shows target placements only.
2. **BlueStacks:** portrait content fitted to screen, right-side Android Back/Home/Recents rail, left view switcher, direct keyboard access.
3. **Windows:** readable zoom, trackpad-style control bar, minimap, prominent switcher and keyboard controls.
4. **Codex:** chat-first hierarchy, current task status, grouped technical logs and access to the live task.
5. **Recovery:** connected host status separated from failed preview state, actionable Retry and alternate targets.

Open [`MIRPG-Remote-UI-Review.fig`](../MIRPG-Remote-UI-Review.fig) in OpenPencil or open [`review-gallery.html`](../review-gallery.html) for a visual walkthrough. Individual PNGs are in `../exports/`.

## Visual QA and limits

- The mockups use the project's **existing graphite/mint theme** (background `#101416`, raised `#242C30`, accent `#70D8C1`), with five **393 × 852** phone artboards. Example content, latencies, and fps are illustrative, **not live measured values**.
- Editable `.fig` file generated headlessly and exported to PNG. OpenPencil lint: **0 errors**, **332 warnings** (281 hardcoded prototype colors, 31 sub-12-pixel labels, 20 small hit-target geometry flags). Before final implementation, bind semantic color tokens, raise tiny text sizes, and provide minimum 48dp interactive hit areas.
- OpenPencil's **live desktop MCP connection** did not respond, so the edit/export path used the local headless CLI. Fresh phone screenshot capture was not possible because the local ADB daemon failed to start. This is a **proposal based on supplied screenshots and source**, not proof of deployed UI parity.
- No APK built or installed, no stream performance measured, and no Git push or release performed.

## Implementation acceptance checks (when authorized)

- Verify both physical Windows monitors show fresh preview frames; expired frames become visibly stale and retry without losing the host connection.
- Open and switch BlueStacks portrait instances; test Back/Home/Recents, tap targeting, orientation, full-screen fit, and keypad on the actual phone.
- Confirm zoom, scroll, right-click, keyboard, monitor switching and touch controls at 2560 × 1440 source resolution.
- Compare screenshot of deployed Codex thread with design using an **expanded 500+ character command**, a running task, and a finished task.
- Trigger an offline host, failed preview, closed guest and stale stream: each should provide an accurate recovery action and keep navigation usable.
